# Spec M5.3 — pemeriksa voice over dengan Muse Voice Transcribe (H-113)

Status: revisi 2 (menyerap pemeriksa L3 putaran 1: 2 BLOCKER, 8 SHOULD, 7 NIT; `_kerja/orkestrasi/l3/hasil-L3-voqa-spec.md`). Mandat: H-113 (`docs/DECISIONS.md`), `AGENTS.md` pengecualian ketiga. Bukan slice Tier 1; skenario di bawah bukan butir evaluasi (H-006) dan tidak memengaruhi angka hasil. Alat QA video, bukan fitur produk: tidak tampil di UI, R1/R6, atau ekspor replay.

## 1. Sumber API (primer, diakses 2026-10-30)

| Hal | Nilai | Sumber |
|---|---|---|
| Model ID | `muse-voice-transcribe-1.0` | https://dev.meta.ai/docs/speech-to-text |
| Endpoint berkas | `POST {MUSE_BASE_URL}/asr/transcribe` (`https://api.meta.ai/v1/asr/transcribe`), `multipart/form-data`, header `Authorization: Bearer` | https://dev.meta.ai/docs/api-reference/voice/transcribe |
| Bagian multipart | `request` (JSON, `application/json`) dan `audio` (`audio/wav`) | idem |
| `request` | `model` (wajib), `audioEncoding` = `WAV` (wajib, satu-satunya nilai), `mode` `PUSH_TO_TALK` (bawaan) / `ENDPOINTING` / `DIARIZATION`, `keywords` (array string; bias, tidak menjamin ejaan), `languageBias` (array nama bahasa, mis. `["English"]`) | https://dev.meta.ai/docs/api-reference/voice/schemas |
| Format audio | RIFF/WAVE, mono, PCM integer 16-bit, 16 kHz atau 24 kHz | speech-to-text (16-bit), schemas (mono, 16/24 kHz) |
| Batas | badan <= 32 MB (413), audio <= 10 menit (400) | speech-to-text |
| Respons JSON | `{sessionId, transcript, audioDurationMs, turns[]}`; `turns` kosong pada `PUSH_TO_TALK`. Tanpa timestamp per kata dan tanpa skor keyakinan | schemas, speech-to-text |
| Harga | $0.18 per jam audio, per detik utuh dibulatkan ke bawah | https://dev.meta.ai/docs/pricing-rate-limits |
| Galat tidak ditagih | permintaan gagal dan 429 tidak ditagih | speech-to-text |
| Batas laju | 256 stream serentak, 16.000 stream per jam per tenant; tanpa RPM | pricing-rate-limits |

Harga dalam micro-USD: 180.000 per jam = 50 per detik.

## 2. Konfigurasi

- `config/model` (H-113: model ID dipin di sini): `[profiles.meta_voice]` = provider `meta_voice`, model `muse-voice-transcribe-1.0`, `api = "asr_transcribe"`, `base_url_env = "MUSE_BASE_URL"`, `api_key_env = "MUSE_API_KEY"` (key Model API yang sama; bukan key kedua), `roles = ["voice_qa"]`, `for_reported_numbers = false`; `[pricing.meta_voice] audio_per_hour_micros = 180000`.
- Penjaga produk (jalur utama tidak berubah perilaku):
  - `build_settings` menolak `api` yang tidak dikenal (`responses`, `chat_completions`, atau tidak ada) dengan `config_invalid` sebelum jaringan; `SparkClient` tidak bisa memakai `meta_voice` (bukan kebetulan bentuk pricing).
  - `/api/health` `model_profiles` melewati profil `api = "asr_transcribe"`: daftar R1 tetap 4 profil (canary S8 tidak berubah), U3/W2/W6/CLI pembanding tidak melihatnya (`roles` tanpa a/b/c juga menolak).
  - `config/budget` TIDAK diubah; `KINDS`, frontend, R1/R6 TIDAK diubah.
- Konsekuensi yang tidak bisa dihindari dari H-113: `config_hash` jalur utama (`config_hash({"model", "budget"})`, tampil di R1 dan di field `config_hash` RunRecord Spark baru) berubah karena isi `config/model` berubah. Kunci cache Spark, grid, dan measure tidak memuatnya (cache tidak terbuang). Test golden S19/S8 yang mengunci hash itu (H-103) di-rebase TERBATAS: hanya string hash lama diganti hash baru di fixture; bukti = fixture lama dengan penggantian string itu identik byte dengan fixture baru. Commit terpisah, butuh persetujuan L1/operator; alternatif yang ditolak di bawah. `test_model_ids_are_contributor_only` dipersempit: tepat satu profil non-Spark tambahan dengan `model == "muse-voice-transcribe-1.0"`, `roles == ["voice_qa"]`, `for_reported_numbers is False`, `api == "asr_transcribe"`.
- `config/voice_qa.toml` (baru, `version = 1`, hanya dibaca alat ini): `profile = "meta_voice"`, `mode = "PUSH_TO_TALK"`, `language_bias = ["English"]`, `keywords = []` (bawaan kosong: bias bisa menutupi salah ucap merek; operator boleh mengisi), `wer_review_threshold_bp = 1000`, `timeout_s = 120`, `limit_micros = 50000` (H-113, gerbang ketat `<`), `scenes = ["S0","S1","D1","D2","D3","D4","D5","T1","I1"]`, `joined_terms = ["bm25"]`.

Alternatif yang ditolak: (E) model ID di `config/voice_qa.toml` tanpa menyentuh `config/model`: nol perubahan jalur utama, tetapi melanggar teks H-113 dan AGENTS ("model ID dari `config/model`"); tersedia bila operator memilih hash utama tetap. (A') record di `runs/spark/records` dengan `provider_cap_micros.meta_voice`: record tampil di U8, R6, dan `runs.json` replay publik (bertentangan dengan "tidak masuk produk") dan gagal terbuka ke pool default bila entri cap hilang (L3 B2).

## 3. Masukan

- Direktori VO (`--vo-dir`): berkas `NN-<adegan>.wav` dengan `<adegan>` di `scenes`; berkas lain (`10-alt-S0-B.wav`, `.mp3`) dicetak "skipped". Adegan ganda, atau adegan `scenes` tanpa berkas = galat sebelum panggilan (keluar 2).
- Naskah: kolom "Voice over (Inggris)" tabel "Storyboard terkunci" `docs/VIDEO.md`, satu baris per ID adegan. Bila operator memakai audio alternatif, baris terkunci VIDEO.md diperbarui dulu (alat tidak membaca naskah di luar repo). `--dry-run` mencetak sha256 naskah per adegan dan 6 kata pertamanya.
- Konversi lokal (numpy, sudah dipin): WAV PCM integer 16-bit saja (lain = galat); stereo -> rata-rata kanal; 16/24 kHz apa adanya; kelipatan bulat 24 kHz (48 kHz) -> FIR low-pass windowed-sinc (Blackman, 129 tap, cutoff 0,45 x laju tujuan) + desimasi; laju lain -> galat. Hasil hanya di memori. Durasi > 600 s atau badan > 32 MB -> galat sebelum panggilan. Versi konversi = `"r1"`.
- Klien HTTP: `urllib.request` stdlib dengan multipart buatan sendiri; tanpa dependensi baru. Transport bisa disuntik (test).

## 4. Biaya, gerbang, cache, store

- Store terpisah `runs/voice_qa/` (tidak dibaca produk): record `runs/voice_qa/spark/records/<run_id>.json` (`store.save_record(runs/voice_qa, ...)`), cache `runs/voice_qa/spark/voice_qa/<key>.json` (`store.cache_write`/`cache_read`/`origin_record`). Pool `meta_voice` = `Ledger(runs/voice_qa).spent()`: pool terpisah secara fisik, tidak mungkin jatuh ke pool default.
- Proyeksi per berkas = `ceil(ceil(frames/rate) x audio_per_hour_micros / 3600)` (batas atas; tagihan membulatkan ke bawah).
- Biaya nyata panggilan sukses = `ceil(floor(audioDurationMs/1000) x audio_per_hour_micros / 3600)`.
- Gerbang sebelum panggilan pertama: `belanja pool + proyeksi berkas yang belum di-cache < limit_micros` (ketat; ini juga menjamin proyeksi run < 50.000). Gagal -> keluar 2, 0 panggilan. Berlaku juga di `--dry-run` (vonis dicetak).
- Kunci cache = `sha256(canonical_json(["meta_voice", model, request_json_kanonik, sha256_berkas_audio_asli, "r1"]))`; `request_json` memuat `mode`, `languageBias`, `keywords`. Hit -> 0 panggilan, record asal lewat `origin_record`. Hanya status `ok` yang di-cache.
- Satu upaya per berkas, tanpa retry. Run sah = satu kali setelah izin L1; berkas yang gagal hanya dijalankan ulang atas izin L1 (cache mencegah panggilan ulang berkas `ok`).

## 5. RunRecord (DATA-CONTRACTS §12, store terpisah)

`run_id = uuid4().hex` (`origin_record` mensyaratkan alfanumerik), `kind = "voice_qa"`, `created_at` UTC, `cache_key` §4, `corpus_hash = sha256 berkas audio asli`, `config_hash = config_hash({"model", "voice_qa"})`, `clean_sha256 = null`, `loader_rules_version = null`, `prompt_version = "vo_qa.r1"`, `prompt_hash = null`, `model` dari config, `effort = null`, `tokenizer = null`, `embedder = null`, `packing = null`, token `0/0/0` (tidak ditagih per token), `cost_usd_micros` §4, `projected_cost_usd_micros` null kecuali di bawah, `latency_ms` terukur, `host` dari `config/model`, `device = "remote"`, `provider = "meta_voice"`, `quantization = null`, `failed_settings = null`.
Galat (`status = "error"`, `error = {code, message}`): HTTP 4xx/5xx/429 -> `code = "http_<status>"`, cost 0 (tidak ditagih); timeout/koneksi -> `code = "timeout"`/`"connection_error"`, `projected` = proyeksi berkas; 200 tanpa `transcript` string atau `audioDurationMs` integer >= 0 -> `code = "usage_invalid"`, `projected` = proyeksi (pola H-063). Pesan galat = teks tetap milik alat + `message` API yang dipangkas 200 karakter; key, base URL, dan host disensor dari semua pesan, record, cache, laporan, stdout. Tidak di-cache.
DATA-CONTRACTS §12 mendapat catatan: `kind = voice_qa` dan `provider = meta_voice` hanya ada di store `runs/voice_qa/` (H-113), bukan di `runs/spark/`.

## 6. Normalisasi teks (sama untuk naskah dan transkrip; WER dan angka dihitung SESUDAH normalisasi)

1. NFKC, huruf kecil, kutip lengkung -> lurus, `&` -> `and`, `%` -> ` percent`, `$X` -> `X dollars`.
2. Angka bertulis: `1,783` -> `1783`; titik desimal hanya bila diapit digit (`1,926.` akhir kalimat = `1926`); `1/10` -> `0.1`; digit+akhiran: `300k` -> `300000`, `5.8x` -> `5.8 x`. Token huruf+digit (`bm25`) tetap utuh; pasangan `bm` + `25` digabung lewat `joined_terms`.
3. Tanda hubung -> spasi; tanda baca (`, ; . : ! ? ( ) "`) dibuang tetapi memutus rangkaian angka.
4. Rangkaian angka (kata dan digit dicampur) -> satu token per bilangan: `three hundred thousand` = `300 thousand` = `300000`; `forty seven thousand` -> `47000`; `one thousand seven hundred eighty three` -> `1783`; `three hundred and two` -> `302`; `a million` = `million` (tanpa pengali) = `1 million` -> `1000000` (`a` numerik hanya sebelum hundred/thousand/million); `one point three` = `1 point 3` -> `1.3` (`point` desimal hanya diapit bilangan/digit kata); `fifty six` -> `56`. Gaya baca berpasangan: satuan/belasan diikuti satuan/belasan/puluhan, atau puluhan diikuti belasan/puluhan = penggabungan string: `eight sixteen` -> `816`, `nineteen twenty six` -> `1926`, `one forty two` -> `142`, `eight one six` -> `816`. Konsekuensi yang dinyatakan: rangkaian tanpa pemisah `eight sixteen seventeen eighty three` -> `8161783` (berbeda dari naskah `816 of 1,783`, jadi `fail`, tidak lulus palsu).
5. `(a|one|1) tenth` / `10th` -> `0.1`; `N cents` (N bulat < 100) -> `0.NN dollars`.
6. Angka kanonik: bulat tanpa nol depan; desimal tanpa nol belakang.

Urutan angka naskah VIDEO.md (dikunci V17): S0 `[1, 300000, 1, 6, 1000000, 0.1]`, S1 `[]`, D1 `[102, 3]`, D2 `[1, 2000, 47000, 8, 6, 5]`, D3 `[14, 2]`, D4 `[69, 69]`, D5 `[]`, T1 `[40, 816, 1783, 1.3, 142, 1926, 3]`, I1 `[0.56]` (dihitung ulang dari kode saat implementasi; beda dari daftar ini = temuan).

## 7. Metrik dan laporan

- Per adegan: WER = jarak Levenshtein kata / jumlah kata naskah (integer basis point untuk ambang, 4 desimal di laporan); daftar beda (sub/del/ins) kata naskah vs transkrip; urutan angka naskah vs transkrip.
- Vonis: `fail` bila urutan token angka tidak identik persis; `review` bila angka cocok dan WER bp > ambang; `pass` selain itu (WER bp == ambang = `pass`). Keluar kode 1 bila ada `fail`, 0 bila tidak.
- Laporan: `video/qa/vo-report.md` + `video/qa/vo-report.json`: model, sha256 audio dan naskah, `run_id`, status cache, biaya per adegan dan total, waktu UTC. Tanpa key, base URL, host, atau jalur absolut (nama berkas saja).
- `--dry-run`: membaca + mengonversi audio, naskah, proyeksi, gerbang; mencetak tabel; tidak membaca nilai key (hanya ada/tidak `MUSE_API_KEY`/`MUSE_BASE_URL`), tidak membuka jaringan, tidak menulis berkas.
