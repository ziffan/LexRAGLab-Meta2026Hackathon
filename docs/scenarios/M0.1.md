## Asumsi teknis lain (tetap diusulkan; operator boleh mengubah)

T1. **Kunci config baru di `config/model` `[limits]`**: `backoff_base_s`, `backoff_factor`, `max_429_retries`, `max_wait_s` (spec hanya menyebut `max_rpm`, `timeout_s`, `max_retries`). Tanpa `max_429_retries` loop 429 tak terbatas (T6 keamanan). Nilai uji: `backoff_base_s=2`, `backoff_factor=2`, `max_429_retries=3`, `max_wait_s=120`, jitter 0. Alternatif: konstanta di kode (melanggar "nilai bisa berubah ada di config/ berversi").
T2. **Record cached/replay**: `cost=0`, usage `null` (lihat O-7).
T3. **`Retry-After`**: bila valid (angka ≥ 0, detik), tunggu = nilai itu (otoritatif, termasuk 0 dan 1 yang lebih kecil dari backoff 2); bila tidak ada atau tidak valid ("abc", "-5", kosong), pakai backoff config. HTTP-date opsional (S16e bersyarat). `Retry-After` > `max_wait_s` → berhenti `rate_limited`, `= max_wait_s` → masih menunggu (batas inklusif). Alternatif: `max(Retry-After, backoff)`.
T4. **Pembatas laju**: jendela geser 60 detik, awal-request di jendela mana pun ≤ `max_rpm`; setiap upaya jaringan (termasuk retry timeout dan 429) dihitung; cache hit tidak. Config nyata `max_rpm=140`; `max_rpm ≥ 150` ditolak (`config_invalid`). Alternatif: jarak minimum 60/max_rpm detik (lolos S13 dengan toleransi 1 ms).
T5. **Proyeksi cost guard**: per panggilan tak-ter-cache = biaya (O-1) dari `est_input` (tokenizer lokal, diberikan pemanggil), `cached=0`, `est_output = max_output_tokens`; proyeksi batch = jumlah proyeksi per panggilan; hanya kunci unik yang belum di cache; batas inklusif (proyeksi + belanja ≤ batas lolos). Alternatif: kasus terbaik dengan diskon cached (berisiko undercount).
T6. **Buku belanja** = jumlah `cost_usd_micros` semua `RunRecord` tersimpan (semua provider/peran, termasuk `status=error` berusage), cakupan total = cap efektif D1 (Meta + OpenRouter digabung, komentar `config/budget.toml`). Record `cost=null`: lihat O-3.
T7. **Base URL tidak dicetak** (komentar `config/model.toml`): host dari `MUSE_BASE_URL` tidak boleh muncul di log/record/pesan galat. Alternatif: host boleh, key tidak.
T8. **Kunci cache** tujuh komponen (`ARCHITECTURE.md` §8): provider, model, quantization, effort, prompt_hash, schema_hash, input_hash; tanpa `prompt_cache_key` maupun key API.

## Skenario

Notasi: `cost(i,c,o)` = biaya per aturan 1 dengan `uncached = i − c`. Pembilang dalam satuan micro-USD × 1.000.000 (jadi pembagian oleh 1.000.000 memberi micro-USD).

### S1 — Biaya panggilan nyata #1 (tanpa cache)
- Masukan: transport membalas 200, `status:"completed"`, keluaran sah `SchemaX`, `usage{input_tokens:3247, input_tokens_details{cached_tokens:0}, output_tokens:445, output_tokens_details{reasoning_tokens:370}}`. Harga default.
- Langkah hitung: uncached = 3247−0 = 3247. 3247×100000 = 324.700.000; 0×2000 = 0; 445×200000 = 89.000.000. Jumlah 413.700.000. /1.000.000 = 413,7. Ceil = 414.
- Jawaban yang diharapkan: `cost_usd_micros = 414` (bertipe int, tertulis `414` di JSON, bukan `414.0`); `usage_input_tokens=3247`, `usage_cached_tokens=0`, `usage_output_tokens=445` (bukan 815 dan bukan 75).
- Bug yang ditangkap: floor (413); reasoning ditambahkan lagi di atas output (445+370=815 → 163.000.000 → total 487,7 → 488); reasoning dikurangi dari output (75 → 15.000.000 → 339,7 → 340); float (`414.00000000000006` dll.); biaya disimpan sebagai float USD.

### S2 — Biaya panggilan nyata #2 (prefix kena cache) dan jumlah
- Masukan: dua panggilan berurutan, `input_hash` berbeda (ekor beda), `prompt_cache_key` sama `pck-synth-1` dari pemanggil. Balasan #1 = usage S1. Balasan #2: `input_tokens:3247, cached_tokens:3185, output_tokens:452 (reasoning 377)`.
- Langkah hitung #2: uncached = 3247−3185 = 62. 62×100000 = 6.200.000; 3185×2000 = 6.370.000; 452×200000 = 90.400.000. Jumlah 102.970.000 → 102,97 → ceil 103. Jumlah buku: 414 + 103 = 517.
- Jawaban yang diharapkan: record #2 `usage_cached_tokens = 3185` (> 0, kriteria selesai ke-2), `cost_usd_micros = 103`; jumlah dua record = 517 (sama dengan belanja smoke `HASIL.md`). Kedua request membawa `prompt_cache_key = "pck-synth-1"` identik. Transport menerima 2 panggilan (kunci cache hasil beda, jadi #2 tidak dilayani dari cache hash).
- Bug yang ditangkap: uncached tidak dikurangkan (input penuh + cached: 324.700.000+6.370.000+90.400.000 = 421,47 → 422); cached dianggap gratis (6.200.000+90.400.000 = 96,6 → 97); floor (102); reasoning ganda (o=829 → 178,37 → 179); reasoning dikurangi (o=75 → 27,57 → 28); `prompt_cache_key` hilang atau berbeda antar panggilan.
