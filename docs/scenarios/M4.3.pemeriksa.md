## Ringkasan

PERLU-PERBAIKAN
- **P1. `chunk_set_hash` atas daftar `chunk_id` tidak menangkap perubahan isi.** `chunk_id = hash(doc_id,start,end,chunker_key)` tanpa teks (`backend/chunking/model.py`). Profil `P1` dengan `corpus_hash` dipalsukan ke hash korpus {d1x,d2} (d1x = d1 dengan isi lain, offset sama) lolos W8 dengan `ok:true`: offset sama, chunk_id sama, hash sama. S3 berjudul "peka terhadap isi potongan", padahal hanya peka terhadap offset/parameter. Hanya `corpus_hash` yang menjaga isi, dan tidak ada skenario yang menguji hash potongan sendirian. Tambahan: sudah ada `chunk_set_hash` lain di `backend/retrieval/dense.py:79` (model, revisi, `(chunk_id, teks)`), yang kunci cache embedding (ARCH §8). Dua fungsi bernama sama dengan isi berbeda. A2 harus memutuskan: satu fungsi bersama (profil dan cache embedding, termasuk teks) atau nama berbeda. Kriteria "hash potongan sama dengan run asal" butuh nilai yang sama dengan yang dipakai grid/cache embedding; `RunRecord` (§12) tidak punya field `chunk_set_hash`, jadi "run asal" tidak punya pembanding tersimpan. Skenario perlu menetapkan pembanding itu.
- **P2. `structure_handwritten` tidak diuji sama sekali.** Itu chunker bawaan UU PT (H-012) dan kandidat profil terbaik. Tidak ada skenario ekspor/impor dengan `schema = null`, `chunk_size/overlap = null`, dan `chunker_key` yang memuat versi parser/aturan. S15(k) hanya menguji penolakan `fixed_size` cacat. Implementasi yang gagal pada handwritten (mis. KeyError pada parameter null) lolos.
- **P3. Penolakan korpus untuk akta tidak diuji.** S4/S5/S6 semuanya UU PT; S5(c) hanya membuktikan korpus akta tidak memengaruhi UU PT. Implementasi yang melewati cek `corpus_hash`/`clean_sha256` untuk `family = akta` lolos semua. Tambahkan: profil `PA1`, korpus {da'} → 409 `hash_mismatch`.
- **P4. Nullability `mean_token_precision` dan `mean_span_recall` tidak dipisah.** S9(a) hanya kasus keduanya null. Butir bergold dengan `retrieved_tokens = 0` memberi `span_recall = 0,0` tetapi `token_precision = null` (EVAL-SPEC §5): implementasi yang mengikat kedua null pada satu kondisi, atau mengganti precision null dengan 0, lolos. Tambahkan varian held-out {butir bergold, retrieved_tokens 0} → recall `0,0` (bukan null), precision `null`, `fully_covered {0,1}`.
- **P5. Urutan `chunk_set_hash` dan urutan muat tidak diuji bersama.** A2 menyatakan terurut menurut (`doc_id`,`start`), tetapi fake selalu mengembalikan urutan baku dan S5(a) hanya menguji `corpus_hash`. Implementasi yang meng-hash urutan keluaran chunker (bukan terurut) lolos. Tambahkan: fake mengembalikan potongan urutan terbalik / dokumen urutan `[d2,d1]` → `chunk_set_hash` sama.
- **P6. A4 (`created_at` dari jam suntikan) bertentangan harfiah dengan ARCH §10** ("profil identik byte per byte") dan baris Reproducibility. Skenario memilihnya sebagai asumsi, tetapi ini mengubah kontrak keluaran yang dijanjikan; perlu keputusan operator eksplisit (atau catatan revisi ARCH §10), bukan hanya baris asumsi. Alternatif A4 (`created_at` run asal) membuat S13 berbeda penuh (badan T1 = T2).

CATATAN
- C1. A10 (`held_out.mean_*` nullable) memang bertentangan dengan §11 tabel; konsisten dengan H-059/H-061 untuk GridPoint. Revisi §11 diperlukan sebelum kode. Benar ditandai penyusun.
- C2. A1 membatasi `corpus_hash` ke dokumen satu keluarga; §11 menulis "semua `CorpusDoc.sha256`". Penafsiran ini dikunci S5(c). Layak ditegaskan operator, bukan sekadar default.
- C3. Urutan prioritas pesan bila `corpus_hash` dan `loader_rules_version` sama-sama beda tidak ditetapkan (S4 vs S6). Kedua 409; hanya isi pesan yang ambigu.
- C4. S5(b) menggantung antara dua pilihan A1 ("apa pun pilihannya"); untuk test harus satu perilaku. Pilih A1 utama saja dan hapus kalimat alternatif dari kriteria lulus.
- C5. S11 tidak menyatakan nilai rata-rata RR dan Recall@K per asal/mode, dan tidak memuat angka ringkasan Recall@K; kolom ringkasan yang tidak dihitung tidak bisa diuji. Nyatakan apakah ringkasan hanya recall/precision.
- C6. Hybrid retrieval, `header_b = true`, dan `packing = truncate` tidak punya skenario ekspor. Tidak memengaruhi potongan, risiko rendah; cukup S14 diperluas satu baris untuk `header_b = true`.

## Kesesuaian spec
- Kriteria 1 (hash potongan sama dengan run asal): S1/S2/S7/S16 menguji round-trip terhadap ekspor, bukan terhadap run grid asal; lihat P1.
- Kriteria 2 (korpus beda ditolak, pesan jelas): tercakup untuk UU PT; akta kurang (P3). Kalimat pesan sesuai UI-SPEC U7 dan DATA-CONTRACTS §11.
- Held-out hanya UU PT, akta per butir tanpa label held-out, hitungan mentah: sesuai EVAL-SPEC §9, H-054, H-059.
- Kode galat W7 sesuai API.md §1 (400/404/422). S18(d) `family = "xyz"` → 404 adalah pilihan penyusun; sah, tidak bertentangan.
- Replay: `X-Replay` header dan "hanya baca `runs/` dan `data/`" (API §1) konsisten dengan A8.
- A10 vs §11 dan A4 vs ARCH §10 adalah dua pertentangan spec yang nyata (C1, P6).
