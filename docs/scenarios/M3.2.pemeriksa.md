## Ringkasan
BLOCKER 2, PERLU-PERBAIKAN 8, CATATAN 6. Semua hitung tangan cocok (nol selisih). Dua BLOCKER: (B1) S12 menuntut skor BM25 > 0 yang gagal pada backend BM25 repo; (B2) A2/S9 (header per unit) bertentangan dengan S4/S5 (header per `chunk_id`) dan dengan DATA-CONTRACTS §7 / SPARK-ROLES §3.

Temuan:
- **B1 BLOCKER — S12 "c2 skor > 0" tidak lolos pada implementasi yang benar.** `backend/retrieval/bm25.py` memakai `rank_bm25.BM25Okapi`. Dengan N=2 dan istilah `ZZ` hanya di satu dokumen, idf = ln((2-1+0.5)/(1+0.5)) = 0 sehingga semua skor 0. Diverifikasi di `.venv`: `get_scores(['zz']) = [0.0, 0.0]` untuk korpus on S12. `BM25Index.rank` tetap mengembalikan c2 (filter irisan istilah, skor 0.0), jadi "c2 peringkat 1" lolos tetapi "skor > 0" gagal. Perbaiki: korpus >= 4 potongan (istilah unik muncul di 1 dari >= 4), atau assert pada keanggotaan dan peringkat, bukan nilai skor.
- **B2 BLOCKER — A2/S9 vs S4/S5 vs spec.** DATA-CONTRACTS §7: `HeaderB.chunk_id` "harus sama dengan potongan yang diminta"; SPARK-ROLES §3: satu potongan per panggilan. S4/S5 mencari header menurut `chunk_id`. S9 mencari menurut unit (header Pasal 1 dipakai X dan Y). Kedua model tidak bisa jadi satu store: S9 tidak menyebut `chunk_id` mana yang menyimpan header unit. Fixed-size melintasi unit, jadi "header unit pertama" juga tidak ada di spec (hanya `Chunk.address` yang memuatnya). Putuskan A2 dulu; bila per-unit, S4/S5 harus menyebut kunci unit; bila per-`chunk_id` (bacaan spec yang paling literal), S9 ditulis ulang (granularitas menentukan potongan mana yang diminta ke B, bukan resolusi unit).
- P1: celah runner (lihat Daya gigit).
- P2: tokenizer header.
- P3: S4 ambigu (raise vs lanjut; chunk di luar `P`).
- P4: A8 salah di `skip`.
- P5: S9 first-vs-last tidak menggigit.
- P6: S7 tidak menguji titik on yang mendominasi titik off, dan seri.
- P7: S8 klaim "tidak ada galat header hilang untuk s3" kosong karena store penuh; tidak menjelaskan interaksi dengan `config/grid.toml header_b=[false,true]` dan `expand` Cartesian penuh (M1.4 A15).
- P8: S13: A10 menyebut "`run_id`/hash isi store" sekaligus; belum diputus.

## Kesesuaian spec
- Kriteria 1 M3.2 ("lebih sedikit teks sumber"): skenario melemah ke `<=` dengan `=` di B=8 dan 21 (A8). Matematis benar untuk `stop` (prefiks on adalah subhimpunan prefiks off). **Tidak benar untuk `skip`** bila header berbeda antar potongan: C=(a: sumber 3, header 5), (b: sumber 4, header 1), B=6, `skip` -> off sumber 3, on sumber 4. A8 harus dibatasi ke `stop` (default); S10 memakai `skip` jadi jangan ada assert invarian di sana. Operator perlu mengonfirmasi pelemahan `<` -> `<=`.
- Kriteria 2 (span di teks sumber): S6, S12 cukup; screenshot di luar skenario (A13).
- EVAL-SPEC §3 dan §5 dipatuhi (cost = tok(hdr)+tok(teks); header tidak gold). Rank = posisi di `P` (§6) dipakai konsisten.
- A1 (frontier gabungan) sebenarnya sudah diputus oleh DATA-CONTRACTS §10: `Frontier` keyed `(family, split, budget_tokens)` tanpa `header_b`, dan dominasi §9 tidak mengenal deret. Bukan pilihan operator; alternatif per deret bertentangan dengan kontrak. Cukup tulis sebagai "mengikuti §10".
- A3 diputus oleh EVAL-SPEC §2 (satu tokenizer lokal untuk semua `tok(.)`) dan §5; A11 diputus oleh H-004/EVAL-SPEC §3. Bukan pilihan, hanya konfirmasi.
- A6: MILESTONES (tabel pemicu baris 4) dan SPARK-ROLES §3 hanya mengatakan "hanya setting di frontier"; frontier mana (tune, header-off) memang belum ditulis spec, jadi A6 sah sebagai usulan. Kutipan "H-049 butir 6" tidak ditemukan di docs repo (EVAL-SPEC §8 tidak bernomor butir 6); verifikasi atau hapus.
- `config/grid.toml` `header_b = [false, true]` dan `expand.py` sudah menghasilkan kembaran untuk semua setting (A15 M1.4). Skenario harus menyatakan lapisan mana yang menyaring menurut `scope`.
- S12 melanggar perilaku backend BM25 nyata (B1).
- A9: `ItemMetrics` tanpa token header; turunan `retrieved - Σ tok(sumber P)` bisa dipenuhi test; tidak ada konflik.

## Asumsi
- Sudah diputus spec (bukan pilihan): A1, A3, A11 (di atas). A5 sebagian: H-046 mewajibkan `clean_sha256` sama; hanya mekanismenya (cek lewat `RunRecord`) pilihan.
- Dikunci diam-diam: S9 mengunci resolusi header per unit (A2) walau SPARK-ROLES/§7 menyiratkan per potongan; S10 mengunci `packing=skip` walau default `stop`; S13 mengunci "R6 menghitung dari cache R1" (mensyaratkan cache tidak timpa, wajar tetapi tidak ditulis di ARCHITECTURE §8).
- A4 (galat) sejalan dengan ARCHITECTURE §10 failure mode ("ditolak, tidak di-cache sebagai sah"); sah sebagai pilihan.
- Pilihan operator nyata: A2, A6, A9 (field baru), A10 (komponen kunci), A8 (`<=`).
