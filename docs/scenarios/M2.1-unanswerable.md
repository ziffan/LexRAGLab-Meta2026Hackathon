## Pilihan terbuka (Dipilih = dipakai skenario; alternatif tidak diuji)

- **P1, skema keluaran.** Dipilih: skema baru terpisah `ProposalU` (`strict: true`, nama skema baru): `{usulan: [{query: string, doc_id: string, alasan_kode: enum, alasan_teks: string}]}`, `additionalProperties: false`, semua field wajib. `alasan_kode` ∈ {`data_tidak_dimuat` (data yang sengaja tidak ada, H-041: NIK, NPWP, rekening), `di_luar_akta` (fakta di luar akta: peristiwa sesudah akta, pihak lain), `rincian_tidak_diatur` (akta mengatur hal umum, rincian ini tidak diatur)}. `alasan_teks` kalimat bebas tak kosong. Tanpa `mode`, `teks_gold`, `start`, `end`. Alasan: enum membuat laporan dapat dikelompokkan, teks bebas membuat operator paham; tanpa field span Spark tidak bisa mengarang gold (H-087 "tanpa gold span"). Alternatif ditolak: memperluas `ProposalD` (`teks_gold` wajib string, mengundang span karangan); hanya teks bebas (tak bisa dikelompokkan).
- **P2, aturan "meragukan" (nilai di `config/proposals.toml` tabel `[unanswerable]`, usulan, tidak dikalibrasi, operator boleh ubah).** Dipilih: `check_top_k = 3`; `lexical_coverage_threshold = 0.5` (inklusif); `generic_df_ratio = 0.5`; `dense_cosine_threshold = 0.80` (inklusif). Unit cari = potongan chunker struktur akta (H-088); test: satu baris = satu potongan. Tokenisasi = tokenizer BM25 `config/retrieval`; SU5, SU6, SU12 menyuntik tokenizer fixture (huruf kecil `\w+`, tanpa stemming, stopword fixture di bawah); SU8 memakai tokenizer produksi persis (stopword + stemmer Sastrawi dari `config/retrieval [bm25]`). Pemeriksaan dan BM25 wajib memakai tokenizer yang sama (satu fungsi). `T(q)` = token isi query berbeda-beda (stopword dibuang). Token **generik** = muncul di unit dengan `df/N > generic_df_ratio`; `T*(q) = T(q)` tanpa token generik. `cov(q, u) = |T*(q) ∩ T(u)| / |T*(q)|`. Himpunan periksa = top-K BM25 ∪ top-K dense. Definisi top-K BM25 = sama dengan `Bm25Retriever.rank`: semua unit yang berbagi ≥ 1 token dengan query, urut skor turun, seri dipecah `chunk_id`, diambil K; idf token yang sangat umum (df 5/6) diganti epsilon positif ala `rank-bm25` (0,25 × idf rata-rata), sehingga token generik tetap mengisi top-K walau tidak dihitung di `T*`. `max_cov` = maksimum `cov` atas himpunan itu. Alasan flag: `lexical_overlap` bila `max_cov ≥ 0.5`; `dense_similar` bila cosine maksimum top-K dense ≥ 0.80; `no_distinctive_terms` bila `T*(q) = ∅`; `dense_unavailable` bila embedder tidak tersedia. `status = doubtful` bila ada ≥ 1 alasan, selain itu `ok`. Alasan memakai `T*` (bukan `T`): istilah umum akta ("Perseroan", "Pasal") ada di hampir semua baris dan akan menandai semua kandidat; skor mentah BM25 tidak dipakai karena bergantung ukuran korpus. Alternatif ditolak: ambang skor BM25 mentah; tumpang-tindih `T` penuh.

## Skenario

### SU1 — Skema `ProposalU` strict, tanpa gold
- Masukan: W4 `{akta-x, [unanswerable]}`; klien palsu mengembalikan berturut-turut (setiap putaran cache kosong): (a) U1-U3 valid; (b) elemen ber-kunci tambahan `teks_gold`; (c) elemen tanpa `alasan_kode`; (d) `alasan_kode = "lain"`; (e) `alasan_teks = ""`; (f) elemen ber-`start`/`end`; (g) `query = "  "`; (h) `{usulan: []}`.
- Langkah hitung: skema `additionalProperties: false`, field wajib 4, enum 3 nilai; (e) dan (g) lolos skema tetapi gagal validasi semantik tak kosong.
- Jawaban yang diharapkan: (a) 200, 3 rekaman. (b), (c), (d), (f) `502 model_error`, 0 rekaman, tidak di-cache sebagai sah. (e), (g) elemen itu dibuang (A5), sisa elemen valid disimpan; bila semua dibuang, 200 dengan 0 rekaman. (h) 200, 0 rekaman, run `status = ok`.
- Tambahan (b)-(d), (f), **persyaratan baru**: jalur tepat. Keluaran tidak sesuai skema ditolak di lapisan klien Spark (`SparkClient.call` → `res.output is None`), yang menurut M0.1 mencatat `RunRecord` galat (biaya/`usage` tercatat); lalu `ProposalService.generate` melempar `ApiError 502 model_error` sebelum `_store_run` (`service.py` ±256-261), sehingga tidak ada `ProposalRecord` dan tidak ada indeks cache. Asersi: klien palsu yang meniru `SparkClient` mengembalikan `res.record` galat; test memeriksa (i) `RunRecord` galat ada di penyimpan run klien dengan biaya tercatat, (ii) service tidak menyimpannya sebagai run sukses dan tidak membuat indeks cache. Bila klien produksi tidak mencatat `RunRecord` galat, itu temuan untuk eksekutor/operator, bukan diasumsikan. W4 yang sama diulang memanggil klien lagi (panggilan +1).
- Bug yang ditangkap: skema `ProposalD` dipakai (span dikarang diterima); `strict` tidak ditegakkan; enum diterima bebas; query kosong menjadi usulan.

### SU5 — Pemeriksaan ketiadaan jawaban per kandidat (P2, tabel hitung tangan)
- Masukan: `AKT`, `check_top_k = 3`, ranker BM25 suntikan yang mengembalikan semua unit berbagi token (asersi ranker asli di SU8), dense dimatikan (`max_cosine = null` untuk tabel ini; lihat SU7), kandidat U1-U6.
- Langkah hitung (`T*` = `T` tanpa {pasal, perseroan}):

| ID | `T*(q)` | `cov` terbaik | `max_cov` | alasan | status |
|---|---|---|---|---|---|
| U1 | {nomor, nik, tuan, budi, santoso} (5) | L3: {tuan, budi, santoso} = 3 | 3/5 = 0,6 | lexical_overlap | doubtful |
| U2 | {nomor, npwp} (2) | L4: {npwp} = 1 | 1/2 = 0,5 (= ambang, inklusif) | lexical_overlap | doubtful |
| U3 | {komisaris} (1) | tidak ada baris | 0/1 = 0 | – | ok |
| U4 | {nomor, rekening, bank} (3) | tidak ada baris | 0/3 = 0 | – | ok |
| U5 | ∅ | – | 0/0 → didefinisikan 0 | no_distinctive_terms | doubtful |
| U6 | {gaji, bulanan, direktur} (3) | L3: {direktur} = 1 | 1/3 ≈ 0,333 | – | ok |

- Jawaban yang diharapkan: status dan alasan seperti kolom; `max_cov` tersimpan sebagai pecahan integer `{num, den}` (U5: `{0, 0}`); `config_hash` terisi dan sama untuk keenamnya; semua 6 rekaman tersimpan (U1, U2, U5 `doubtful` tidak dibuang, P3); `validation = null`, `resolved_span = null`.
- Bug yang ditangkap: token generik ikut `T` (U3, U4 menjadi `doubtful` karena "perseroan"); ambang eksklusif (U2 `ok`); pembagi nol di U5; float 0,5 vs 0,5000001 (perbandingan pecahan); kandidat doubtful dibuang; pembilang menghitung token di luar himpunan periksa.

### SU6 — K berpengaruh (ranker suntikan)
- Masukan: U1; ranker BM25 suntikan mengembalikan urutan `[L2, L0, L3, L4, L1, L5]`; (a) `check_top_k = 1`; (b) `check_top_k = 3`.
- Langkah hitung: (a) himpunan = {L2}; `cov(L2)` = 0/5 → `max_cov = 0/5`, `ok`. (b) {L2, L0, L3}; L3 → 3/5 → `doubtful`.
- Jawaban yang diharapkan: (a) `ok`, `top_k` berisi 1 elemen `source: bm25, rank: 1, unit_text: L2`. (b) `doubtful`, `top_k` 3 elemen berurutan rank 1..3. `K ≤ 0` atau bukan integer di config → galat konfigurasi (`config_invalid`) saat dimuat, bukan saat W4.
- Bug yang ditangkap: K dikode keras 3 atau 5; memeriksa seluruh dokumen (a gagal); urutan `top_k` tidak dipertahankan.

### SU7 — Sinyal dense (suntikan) dan ketersediaan
- Masukan: U3 (lexical `ok`). Embedder suntikan mengembalikan top-3 cosine untuk (a) `[0.82, 0.40, 0.10]`; (b) `[0.79, 0.40, 0.10]`; (c) `[0.80, 0.40, 0.10]`; (d) embedder melempar galat tidak tersedia.
