## Lingkup dan konvensi

Yang diuji di sini adalah apa yang BARU di slice B pembanding; mekanisme M3.2 (akuntansi token header, kunci `chunk_id`, A4 `header_missing`, A5 validitas, frontier) dipakai apa adanya dan tidak diulang.

1. Pembanding B = menjalankan peran B (header per potongan) dengan profil non-Contributor (`baseten_open`, `glimmer_local`), menyimpan header di store TERPISAH per profil, lalu menjalankan ulang HANYA kembaran header-on grid dengan store itu. Grid, frontier, profil terpilih, README, U7 dan laporan utama tetap Contributor (H-028, H-100).
2. Kode pembanding hidup di modul baru (nama tidak dikunci skenario); jalur Contributor yang ada (`runs/headers/`, `runs/headers/akta/`, `runs/grid/`) tidak boleh berubah perilakunya, bit demi bit (G-38). SATU pengecualian yang disengaja dan dinyatakan: perubahan pool belanja P6/P9 membuat cap total dan gerbang kumulatif Contributor tidak lagi menghitung belanja Baseten (S9 (e), S10; Q-B2, Q-B8).
3. Uang integer micro-USD; waktu UTC; tanpa float. Biaya per panggilan `ceil((uncached x in + cached x cached + out x out) / 1e6)`.
4. Tokenizer uji untuk validator header: satu token per kata dipisah spasi (deterministik, sintetis). Tokenizer sungguhan dipakai di integrasi, bukan di skenario ini.
5. Harga sintetis "Baseten uji" = nilai `[pricing.baseten_open]` (config): input 1.250.000, cached 150.000, output 4.250.000 micro-USD per 1M token. Harga Glimmer 0/0/0 (config).
6. "Pool" (dipakai di S10, S11): kelompok belanja yang dibandingkan dengan satu plafon. Usulan P6: satu pool per provider yang tercantum di tabel plafon provider, sisanya (meta, openrouter, lmstudio_local) satu pool default.
7. Tidak ada panggilan jaringan nyata; transport diganti spy yang menghitung request. "Sebelum jaringan" = spy mencatat 0 request.

### S17 — Cakupan Glimmer, proyeksi waktu, dan lanjut setelah berhenti (Q-B1, Q-B7, P15)
