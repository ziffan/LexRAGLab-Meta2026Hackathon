## Temuan
- **B1 BLOCKER (SU8, baris 104-105).** "U3 dan U4: tidak ada baris ber-skor > 0 -> top-K kosong; `top_k = []`" salah. Query U3/U4 memuat "perseroan"; `Bm25Retriever.rank` mengembalikan semua baris yang berbagi token (`bm25.py` 76) dan idf token df 5/6 diganti epsilon (positif), jadi top-K = 3 baris ber-"perseroan" (L4, L5, L3; seri dipecah `chunk_id`). Implementasi benar gagal asersi. Perbaiki: `top_k` U3/U4 = [L4, L5, L3], `status` tetap `ok` (T* membuang token generik). Ubah juga kalimat bug "idf negatif": rank-bm25 sudah memakai epsilon; risiko sebenarnya adalah token generik mengisi top-K.
- **B2 BLOCKER (SU15, baris 153).** "`akta.v3` berisi 2 baris atau gabungan" dan "muat ulang = 3 + 2 = 5" ambigu dan salah. Pemuat memakai berkas versi TERBARU saja (`service.py` 415-419); `_stage_item` menulis versi baru = isi terbaru + satu baris (432), jadi dua persetujuan menghasilkan v3 lalu v4. Cabang "2 baris saja" menghilangkan butir v2; 5 mustahil (v2 berisi 1 butir, jadi 1+2 = 3). Tetapkan: v3 = v2 + U1 (2 baris), v4 = v3 + U3 (3 baris), muat ulang = 3 id unik; v1, v2, v3 tak berubah byte.
- S2 SHOULD (P4). `mode = parafrase` untuk butir wajib tolak mencampur butir `gold_spans = []` ke filter mode `parafrase` (SU17 menunjukkan pergeseran 0,5 vs 0,2 pada recall/precision) dan ke `by_mode`. Preseden `kontrol-K-08` (uupt.v13) valid, tetapi dampak laporan perlu ditandai sebagai pilihan operator, dengan asersi `by_mode` setelah persetujuan.
- S3 SHOULD (P10).
