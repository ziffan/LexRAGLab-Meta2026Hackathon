## Kesesuaian spec
- Kriteria selesai M1.4 (H-015/H-049, H-034/H-033/H-055, butir baru, dominasi, cache) terpetakan; tidak ada skenario bertentangan dengan EVAL-SPEC §8-§9 atau DATA-CONTRACTS §4/§10, kecuali F7.
- F7: S10 menuntut `ItemMetrics.split = transfer`, padahal DATA-CONTRACTS §10 mendefinisikan enum `tune` / `held_out` saja; `transfer` hanya ada di tabel laporan EVAL-SPEC §9. Perlu keputusan/perluasan kontrak, atau S10 diubah.
- Agregat spec = rata-rata span_recall per butir (EVAL-SPEC §4), bukan pooled; skenario tak membedakannya (C1).
- Tidak tercakup (diakui penyusun): UI frontier, laporan per asal dan mode (isi EVAL-SPEC §9 Laporan, layak satu skenario bila masuk M1.4), atomisitas cache, butir ditarik setelah split.

## Asumsi
- Sudah diputus spec, bukan pilihan operator: pembanding inklusif "≤ 1 butir" (§9, H-034); urutan sederhana ditulis di config (A7 benar menyerahkan ke operator); `setting_id` leksikografis (S19). A2-A7 dan A9 tepat ditandai sebagai pilihan operator.
- Dikunci diam-diam: (1) ukuran potongan di luar kunci sederhana, dan S18 bergantung padanya (disebut di A7 tetapi tidak sebagai pilihan yang mengubah S18); (2) S6 "RNG tepat satu kali" mengunci urutan implementasi (validasi sebelum acak = nol panggilan sah).

## Rekomendasi perbaikan
1. (F1) S12: ganti dengan kasus yang menggigit. Contoh terhitung: 3 butir gold_chars 10; f-1 covered [0,0,3], f-2 covered [1,1,1], rata-rata eksak sama 1/10; float `sum(x/10)/3` memberi 0.09999999999999999 vs 0.10000000000000002. Hapus klaim bahwa rata-rata 0.1+0.2+0.6 vs 0.3+0.3+0.3 berbeda.
2. (F2) Tambah metrik held-out yang berlawanan di S16, S18, S19 (kandidat terbaik held-out lain dari pilihan tune), atau hapus klaim "held-out dibaca saat memecah seri" dari S15.
3. (F3) S17: ubah urutan mode tiruan jadi non-alfabetis (mis. dense < bm25 < hybrid atau hybrid < dense < bm25) dan sesuaikan jawaban.
4. (F4) Tambah setting `structure_handwritten` dengan overlap null di S16 atau S17 (null dibaca 0), atau hapus klaim bug itu.
5. (F5) S18b: buat precision seri lewat dua rute hitung berbeda (mis. rata-rata per butir 0.1,0.2 vs 0.3,0.3) supaya float memberi 0.30000000000000004 vs 0.3 padahal eksak sama.
6. (F6) S22: pisahkan langkah 4 menjadi (i) hanya `item_set_hash` berubah, (ii) butir ditambah dengan `split_version` naik; perjelas hitungan langkah 4 (setting x semua butir, mis. 27, bila cache per-run) dan bahwa langkah 3 menjaga jumlah setting 3.
7. (F7) Putuskan nilai `transfer` di DATA-CONTRACTS §10 (catat sebagai isu "Menunggu operator") sebelum S10 disetujui.

CATATAN: C1 tambah satu butir dengan gold_chars berbeda (10 vs 30) di S15/S16 untuk membedakan rata-rata per butir dari pooled. C2 S6 ubah "satu kali" menjadi "paling banyak satu kali". C3 S7(d) "mustahil" menjadi "sangat tidak mungkin". C4 S8 tak menguji butir baru `operator` dengan syarat kontrol. C5 S21 mengasumsikan produk Cartesian penuh header_b x mode untuk setiap chunker; konfirmasi ke H-012. C6 butir tanpa gold di held-out tidak diuji (hanya di tune, S16).
