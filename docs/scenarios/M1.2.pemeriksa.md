## Kesesuaian spec
- Tidak ada skenario yang bertentangan dengan EVAL-SPEC §3-§6 atau M1.2. Kriteria 1-5 M1.2 terpetakan (matriks benar).
- S1 "gold terbelah dua potongan" dan tiga kasus wajib M1.2 k.3 ada.
- Bentrok kecil: A1 (gabung span dulu) berbeda dari bunyi harfiah EVAL-SPEC §6 ("memecah setiap span gold"; `parts` = bagian semua gold_spans). Defensible karena G himpunan, tapi ini penafsiran, bukan teks spec.
- Tidak teruji dan tidak disebut: `GridPoint.mean_token_precision` bertipe `number` (tidak null) padahal bisa tak terdefinisi bila semua butir null (spec diam).
- S16 bergantung pada jalur run/RunRecord yang melampaui kalkulator; pastikan operator tahu ini mengikat desain M1.2.

## Asumsi
Sudah diputus spec (bukan pilihan operator, sebaiknya dikeluarkan dari daftar persetujuan): A9 (§4/§9 "rata-rata atas butir"), A10 (§6 eksplisit rank di P), A11 (H-033 a), A12 (§3.2 "selama akumulasi ≤ B"), A13 (§3.3 "lanjut ... yang masih muat"), sebagian besar A2 (§5 "setiap potongan ... ditokenisasi") dan A3(c)/(a) sebagian.
Pilihan operator sungguhan: A1, A3(b) (r<=0 tidak masuk), A4, A5, A6, A7, A8, A2 bagian serpihan-kata. A4 dan A5 mengunci peta alamat (heading tidak masuk unit ber-ayat, tapi masuk unit Pasal tanpa ayat) diam-diam sebagai masukan test; ini asimetri yang harus dinyatakan eksplisit ke operator dan diselaraskan dengan parser struktur nanti.
Dikunci diam-diam: Recall@K = null untuk butir tanpa gold (S7) dan bagian-ayat kosong tidak dibahas.

## Rekomendasi perbaikan
1. (P1) Tambah kasus truncate dengan sisa anggaran setelah header <= 0 (mis. header 2, sisa 2 atau 1) dan tegaskan hasil (potongan tidak masuk, P tidak berubah). Tambah satu kasus truncate dengan potongan bernilai 0 setelahnya, atau hapus klaim "truncate melanjutkan" dari daftar bug S3 karena tidak tertangkap.
2. (P2) Tambah skenario dengan teks token berulang di posisi berbeda (satu gold, satu bukan), plus overlap, supaya dedup berdasarkan teks/id token gagal.
3. (P3) Tambah Recall@K dengan potongan yang tepat sama dengan bagian-ayat ([25,37) atau [12,24)) dan satu dengan end == end bagian tetapi start lebih awal.
4. (P4) Tambah skenario gold yang mencakup heading `### Pasal 1` (mis. [0,50), "seluruh Pasal" menurut DATA-CONTRACTS Item.gold_spans) dan gold yang seluruhnya di luar unit (mis. [51,52) atau [0,11)); tetapkan parts, penyebut Recall@K (null atau 0 bila parts kosong), dan perilaku heading.
5. (P5) Koreksi S15: pooled recall = 18/32 = 9/16 (0.5625), bukan 18/31.
6. (P6, CATATAN) S8: "potongan paling banyak beririsan (c4 -> 1/4)" salah; paling banyak beririsan adalah c3 (2 vs 1) -> 1/3, tidak membedakan. Ganti dengan "potongan terakhir yang beririsan".
7. (P7, CATATAN) Tambah satu skenario non-ASCII/non-BMP (mis. "§", emoji) untuk menjaga offset code point (DATA-CONTRACTS §1).
8. (CATATAN) Pisahkan daftar asumsi: keluarkan A9-A13 (sudah diputus spec) agar persetujuan operator fokus pada A1, A3b, A4-A8.
9. (CATATAN) S4 bug "truncate mengabaikan biaya header (c2' 3 token -> 6/10)": angka tidak dapat diverifikasi dari skenario; hitung ulang atau hapus angkanya.
10. (CATATAN) BM25/Sastrawi dan tabel frontend tidak tercakup (diakui penyusun); pastikan slice M1.2 tidak ditutup tanpa test Tier 2 untuk keduanya.
